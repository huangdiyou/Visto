视频预览与组件安装

Visto 使用 FFmpeg 和 ffprobe 生成封面、预览与媒体信息。

按 macOS 或 Linux 指南使用官网安装脚本时，视频组件会一起安装。Windows 包已经包含这些组件。完成安装后，无需再运行本页的额外命令。

程序和组件可以分别更新；安装工具负责选择兼容组件、下载和验证。普通用户无需填写组件版本、签名或校验值。

组件与程序不在同一目录，卸载 Visto 时它不会被一并删除；重装会复用现有组件。需要彻底清理设备时见第 24 章的删除视频组件。

旧包缺少视频组件

原始 1.0.3 包也可以使用独立安装脚本。在原始解压文件夹打开终端：

curl -fsSL https://visto.akahxh.top/install.sh -o install-visto.sh
# macOS：不要用 sudo，脚本会先以当前用户检查程序，通过后才请求安装权限
bash install-visto.sh --source-dir .
# Linux：使用 sudo
sudo bash install-visto.sh --source-dir .

同版本 Server 已安装时，脚本会补齐视频组件并重启服务，不覆盖项目数据；安装的是不同版本时会停止，请先看维护指南。

这不会把旧包的网页变成新版网页向导；是否有组件状态提示，以实际程序版本为准。

提示 unknown option: --with-media-runtime

原始 1.0.3 安装器不支持这个参数。改用上面的独立安装脚本，不要继续给旧脚本添加它。参数报错本身不会开始安装，无需因此卸载或删除数据。

确认视频能正常使用

在测试项目上传一段短视频，等待处理完成后打开媒体详情，确认预览可以播放。

页面提示缺少视频组件时

“服务器缺少视频处理组件”表示服务器未找到可用的 FFmpeg 或 ffprobe，不能据此判断视频损坏。原文件仍然保留；组件未修复前重复点重试不能解决问题。

  • 工作空间 Owner：从视频详情点“检查视频组件”，或打开 Owner 设置 → 视频组件与编码。
  • 普通项目成员：联系服务器管理员或工作空间 Owner；浏览器所在电脑安装 FFmpeg 不会修复远程服务器。
  • 首次设置允许先创建工作空间，但缺少组件时封面与视频预览暂不可用。

管理员先在运行 Visto 的服务器上检查已有 FFmpeg/ffprobe。后台可复制与服务器平台匹配的本机检查和配置命令；在该实例的安装目录执行，CLI 与服务必须使用相同运行时根。两个程序均存在还不代表编码能力通过，需执行本机 media-runtime inspect 能力检查，或在编码设置中查看实际探测结果。

已有组件兼容就复用；自定义路径需要同时包含两个程序。缺失或不兼容时，按本章对应平台安装步骤取得审核版；断网时使用同平台的离线包、清单和配套签名。不得绕过签名与摘要检查。Windows 正式包自带组件，缺失时先核对解压完整性与服务启动入口；开发预览包可能不包含组件。Docker 应使用含组件的配套镜像，不能套用原生主机安装命令。

配置后重启同一个 Visto 实例，回到后台点“重新检查”。通过后可点“重试最近受影响任务”；该入口只重新排队最近 200 个失败任务中明确因缺少组件失败的媒体任务，逐项显示成功数与失败数。更早的任务在项目媒体详情中重试。页面也会保留磁盘、格式或编码错误等其他原因的失败，避免误重试无关任务。

缺少组件的新任务会在第一次失败后停止自动重试，页面显示等待配置；恢复后仍由用户主动重试。已有可播放预览继续可用，后台增强失败不会移除预览。

失败时怎么处理

现象 怎样处理
下载失败 检查网络后重试，保留具体错误信息
验证失败 停止安装，将错误信息提供给维护者
macOS 阻止程序运行 按 Mac 安装说明允许对应程序，然后重试
安装完成但没有预览 检查媒体处理错误与磁盘空间
只有某个视频无法处理 先用另一段短视频测试，再检查原文件格式
